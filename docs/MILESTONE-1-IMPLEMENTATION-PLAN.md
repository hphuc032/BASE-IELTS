# Milestone 1 implementation plan · v1.6 proposal

Identity foundation only. Execute only after technical and evidence decisions, explicit candidate promotion and separate owner authorization. v1.4 remains standing. Review [owner decisions](MILESTONE-0-PRODUCT-OWNER-SIGNOFF.md), [v1.6](MILESTONE-0-FINAL-v1.6.md), [traceability](MILESTONE-0-TRACEABILITY.md) and [closure](MILESTONE-0-CLOSURE-REPORT.md). Modules below are intended deliverables after authorization.

| Increment | Dependencies | Scope and expected modules | Security invariant | Acceptance, failure and completion gates |
| --- | --- | --- | --- | --- |
| M1.1 · Foundation | TECH-01/02/12 and explicit M1 authorization | Maven wrapper/backend skeleton, Next.js/TypeScript foundation, local config templates, private PostgreSQL connectivity, Flyway/test wiring, CI, health | Approved versions, HTTPS same-origin topology, secrets out of source, dedicated migration/runtime connections | Capture exact versions and resolve Maven access diagnostic; reproducible clean builds and public test fixture without session. Any unapproved dependency or production secret fails gate. |
| M1.2 · Schema | M1.1 and TECH-05/12 | Identity-only migrations for users, roles, memberships, tokens, governance, approvals and audit; nullable relationships and required indexes | SQL status NOT NULL + enum + credential CHECK, one-use tokens, restrictive FK/retention, no credential seed | Disposable real PostgreSQL migrates cleanly and repeat startup succeeds. Reject malformed tuples, dangling references and partial writes via R16-01. No future content tables. |
| M1.3 · Roles and fencing | M1.2 and accepted A1/A2 and TECH-02/05/12 | Migration/owner/runtime roles, fence_guard and exact fence routines, account-revision adapters, narrow denial and lifecycle privileges | Database row before JVM stripe; no direct runtime users UPDATE or sensitive audit mutation; scoped fixed definer context | Inspect catalog grants, deny unlisted calls and role assumption. R15-01 and R16-02 validate privileges, rollback and actual session_user. Broad grant, leaked credential tuple or reversed locks fails. |
| M1.4 · Registration and verification | M1.2/3 and TECH-03/04/12 | PENDING registration, issue/resend/verify, password chosen at verification, volatile development/test mail, bounded admission and cleanup | No pre-verification credentials/auth; token digest only, atomic activation, generic safe responses and protected terminal retention | ID/EM, I13-05 and R16-04 on controlled clock/fault fixtures. Reject early activation, repeated consume, unsafe cleanup, leaked token or provider-free production activation. |
| M1.5 · Authentication and sessions | M1.3, verified fixture from M1.4, TECH-01/02/04/12 | PREAUTH/AUTH scopes, explicit Spring context and token pipeline, cookie/login/logout/profile, account fencing, PREAUTH store and ingress budgets | At most one binding; 60-minute idle/7-day absolute; revision revoke and atomic anonymous cap independent of AUTH storage | SE, R15-01 and R16-05/06 with real browser and DB. Failed cap, stale authority, CSRF, lost/unknown commit or admission target blocks completion. |
| M1.6 · Admin foundation | M1.3/5 and TECH-05/12 | Deployment bootstrap, scoped approvals, cancellation, recovery, audited disablement and last usable Admin, restricted maintenance | Distinct mapped principals, exact one-use payload, real actor audit, no unauthorized ADMIN grants | AD, I14-04 and R16-02/03/04. Unrelated approver, lost actor, partial rollback, stale revision or last-Admin break fails. No public admin recovery route. |
| M1.7 · Auth UI | M1.4/5 | Registration, confirmation/resend, login/logout, profile and expired session/error states only | No premature auth or credential in storage; browser recovery without silent replay | Expected fixture states, correct scoped tokens, reordered responses and expired cookie behavior. Any private hydration leak or ignored disabled state fails. |
| M1.8 · Acceptance | M1.1–7, promoted candidate and approved test parameters | PostgreSQL integration, real role/constraint catalog checks, controlled race and fault suites, browser checks and evidence | Same DB and privileges as approved topology, rollback and known/unknown commit assertions, bounded overload | Run applicable traceability C/D, R15-01 and R16-01–06 plus pure tests. Capture versions, outputs and gate results; no mock-only security or H2 lock proof. Identity-only release review. |

**Production readiness is separate.** Requires real sender/provider, ingress and measured timing/capacity, actual operator mapping and recovery drill, privacy and audit operations. Production email delivery is outside this plan. Reading, Exercise Authoring, Assessment, Vocabulary, Progress and AI integrations are excluded. L-01 expiry worker is an **OPEN M4 IMPLEMENTATION GATE**; no implementation or activation before a resolved M4 contract and TECH-09 approval.
