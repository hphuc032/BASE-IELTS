# Milestone 0 corrected design proposal

**Status** Proposed · Subject to Product Owner approval. See [review and approved decisions](MILESTONE-0-REVIEW.md).

## Logical ERD

UUID identifiers and UTC instants stored as timestamptz are proposed. FK components and unique business keys are required unless marked nullable. Version rows may be edited while drafts and become immutable with their owned rows when published. Keep an independent draft lock revision.

| Entity | Keys, relationships and invariants |
| --- | --- |
| users, roles, user_roles | Unique canonical email and unique role code. Composite PK (user_id, role_id), each an FK. Nullable assigned_by FK to users. Normalize login and registration consistently, without provider-specific alias folding. Insert learner role in the registration transaction. |
| topics, reading_passages | Unique nonblank canonical slugs per entity. Passage has author FK and nullable current_published_version_id. Composite pointer FK (id, current_published_version_id) to passage_versions (passage_id, id). |
| passage_versions | FK to passage, optional topic FK, unique (passage_id, version_no) and (passage_id, id). Version title, summary, visibility, difficulty, CEFR, timing, word count and content. Publish only a validated version with paragraphs. |
| passage_paragraphs, paragraph_translations | Paragraph FK to passage version, unique (passage_version_id, position) and (passage_version_id, id). Translation FK to paragraph, unique (paragraph_id, canonical_language_code). Positions start at one. |
| exercises | Required passage FK for MVP, author FK, nullable current_published_version_id. Composite pointer FK (id, current_published_version_id) to exercise_versions (exercise_id, id). Unique (id, passage_id) for membership. |
| exercise_versions | Composite FKs (exercise_id, passage_id) and (passage_id, passage_version_id) bind the exact passage version of the exercise's parent. Unique (exercise_id, version_no), (exercise_id, id), and (id, passage_version_id). Version instructions, title, visibility, positive exam duration and grader policy revision. Both modes are derived. |
| question_groups, questions | Group FK to exercise version, unique (exercise_version_id, position) and (exercise_version_id, id). Question composite FK (exercise_version_id, group_id), unique (group_id, position) and (exercise_version_id, id). Store type, prompt, positive fixed-precision points and allowlisted constraints. MVP uses one passage version per exercise. |
| question_options and protected marking data | Option FK to question, unique (question_id, option_key), (question_id, position), and (question_id, id). One protected marking row per question. The single-choice key uses a nullable relational option FK (question_id, correct_option_id) with type-dependent validation at publish. Keep enum/text keys in typed protected data, validated against question type. Explanation, keywords, paraphrases and distractor notes belong to the same immutable version. |
| question_evidence | Composite FKs (exercise_version_id, question_id), (exercise_version_id, passage_version_id) and (passage_version_id, paragraph_id). Store paragraph reference plus optional reviewed excerpt/note. Defer character offsets. |
| attempts | FK learner and exact published exercise_version_id. Unique (id, exercise_version_id) for answer membership and (learner_id, start_key) for retry identity. Store canonical start request, mode, state, start time, Exam deadline, submission reason/timestamps and score totals. Each accepted new start gets its own row. |
| attempt_items | PK (attempt_id, question_id). Composite FKs (attempt_id, exercise_version_id) and (exercise_version_id, question_id). Initialize all questions with null answer, false review flag and revision zero. Retain raw answer, revision, saved_at and on finalization persist outcome, awarded and max points even for unanswered items. |
| reading_activity | Unique (user_id, passage_id). Composite FK (passage_id, passage_version_id) and nullable bookmark composite FK (passage_version_id, last_paragraph_id). Keep percent within 0–100. When the public version changes, retain the old record until the user starts progress on the new version. The old bookmark is never applied to the new text. |
| user_vocabulary | FK user, private term/meaning/context/notes/status. Optional sources carry passage_version_id and optional paragraph_id with the same membership FK as progress. Optional shared vocabulary entry FK only if the provider design requires it. If O-08 selects deduplication, use nonnull normalized_term and unique (user_id, normalized_term) with a child source table for multiple contexts. |

Enforce publication-only pointers, positive version numbers, enum domains, version immutability, valid score bounds, deadline/mode consistency and terminal timestamp consistency. Use row checks for row-local invariants and transactional publish/service checks for cross-row conditions such as at least one question and at least two choices. Cap publishable total points to the score precision. Store original grading policy behavior and test fixtures for each revision. Historical review reads persisted results and pinned version content, and historical regrading for verification uses the original policy. A policy fix or content correction produces a new version for future starts.

Restrict physical deletion of published graphs and referenced users/content. Allow draft-owned child deletion only when the draft is unreferenced. Handle account deletion and retention through the approved privacy policy. Publish, withdraw and start transactions use consistent parent lock ordering (passage then exercise) and recheck current eligibility. Publishing an updated passage and moving affected exercise editions can be coordinated in a single transaction. Withdrawing a parent hides its exercise discovery/start, including global routes. The proposal lets existing owners finish and review pinned versions after ordinary withdrawal. Exceptional rights/privacy takedown behavior is open.

For indexes, keep uniqueness-backed child lookups and add only access paths needed by queries. Initial candidates are a partial public publication-date/id index on passage versions with the current-pointer predicate in the query, topic/publication-date for filtered discovery, exercises by passage_id, attempt history by (learner_id, started_at DESC, id), attempts by exercise_version_id for retention, and owner/time indexes for vocabulary and activity. If a deadline sweeper is approved, add a partial deadline index for in-progress timed attempts. Evaluate other referencing-side FK indexes against deletion, join and withdrawal plans, and use stable ID tie-breaks for paging. Avoid separate duplicate indexes on paragraph/group/option positions and attempt items already covered by key prefixes. [PostgreSQL constraints reference](https://www.postgresql.org/docs/current/ddl-constraints.html)

## Session and browser topology

Propose one HTTPS browser origin with Next.js serving UI and an ingress routing /api/v1 to Spring Boot. Keep the backend private from browser-direct access. Use a host-only Secure, HttpOnly session cookie with explicit SameSite=Lax and Path=/api/v1 for client-fetched auth. If personalized SSR is approved, revisit cookie path and forward credentials only to the trusted backend with request-scoped, uncached rendering. Validate trusted proxy configuration and never log cookies or auth bodies. Public Reading does not allocate a session.

Use a server-side synchronizer token. GET /auth/csrf returns a token plus header name and initializes a pre-auth session when needed. Send the token in X-CSRF-TOKEN on unsafe requests, including login, registration and logout. Rotate the session identifier on login and privilege elevation. Clear the prior CSRF token at successful login/logout and fetch a fresh token before the next write. Invalidate sessions on logout, disablement and changes to permissions/password; clear the cookie with matching scope. Enforce server-side idle and absolute expiry. Propose single-instance in-memory sessions if restart-driven reauthentication is accepted; persistent attempts still recover after login. Keep session-store type and timeout values open. Apply generic auth failures, adaptive password hashing, rate limits and auditable role changes. [Spring Security CSRF reference](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)

Same-origin deployment needs no browser CORS exception. If same-site but distinct origins are selected, allow exact approved origins, credentialed fetches and preflight headers including CSRF, Idempotency-Key and If-Match. Run preflights before session checks, and scope cookies to the API host. A cross-site setup needs SameSite=None plus Secure and still depends on browser third-party-cookie policy. Verify the chosen topology in real browsers. CORS and SameSite supplement CSRF checks. [Fetch Standard](https://fetch.spec.whatwg.org/)

## Endpoint and DTO contract

Paths are relative to /api/v1. Use JSON data and page envelopes and structured errors with trace ID. Use 400 for invalid shape/values, 401 for missing session on private routes, 403 for CSRF or authenticated role prohibition, 404 for absent or concealed resources, 409 for state/key conflict, 412 for stale answer revision, 428 for a missing revision precondition and 429 for temporary throttling. Resolve scoped ownership before disclosing entity or state details.

| Endpoint | Gate and shape |
| --- | --- |
| GET /auth/csrf, POST /auth/register, POST /auth/login | Public, CSRF on POST. Registration accepts email, password, displayName only and grants LEARNER. Login accepts email/password and returns safe profile while setting the cookie. |
| GET /users/me, PATCH /users/me, POST /auth/logout | Session required. Profile returns id, email, displayName, roles and status. PATCH allows displayName for the initial contract. Logout returns 204. Reset/verification endpoints depend on O-11. |
| GET /reading and /reading/{id} | Public published/current PUBLIC items. List returns metadata and pagination. Detail includes version ID and ordered paragraphs with permitted translations. No personal fields. |
| GET /reading/{id}/exercises, /exercises, /exercises/{id} | Same current published and PUBLIC predicate for exercise and parent, plus a pinned PUBLIC passage version matching the current public passage pointer. Public cards contain ID, title, summary, both modes and Exam duration. Prompt preview awaits O-06. Apply the same checks to search, slug lookup, counts, media and related links. |
| GET/PUT /reading/{id}/progress | Signed-in learner, own progress on eligible passage. Write accepts passageVersionId, lastParagraphId and progressPercent. Server verifies membership and stamps timestamps. |
| GET/POST /vocabulary, GET/PATCH/DELETE /vocabulary/{id} | Owner-scoped. Accept term, meaning, optional language/IPA/part-of-speech/context and versioned source, as applicable. Derive owner and verify source visibility and membership. Manual save requires no dictionary. |
| POST /attempts | Signed-in learner. Accept exerciseId and mode, plus mandatory Idempotency-Key. Return 201 with Location and safe attempt identity for new starts. |
| GET /attempts and /attempts/{id} | Own history and recovery. Detail contains pinned exerciseVersionId, status, mode, start/deadline/server time, groups, safe questions, saved answers, markedForReview and per-item revisions. Both modes share grading rules. Exam contains English passage and the attempt-safe options/prompts only. |
| PUT /attempts/{id}/answers/{questionId} | Owner only. Accept a complete item representation with typed answer or null to clear, and markedForReview. Use If-Match with the current per-item ETag. Return stored representation with new ETag and savedAt. |
| POST /attempts/{id}/submit, GET /attempts/{id}/result | Owner only. Bodyless submit, returns the committed summary. Result gate requires GRADED. Summary has score/maxScore, outcome counts, timestamps and reason. |
| GET /attempts/{id}/review | Owner and GRADED, or future explicitly scoped role and GRADED. Returns pinned prompts/options, yourAnswer, outcome, intended correct answer or approved variants, points, explanation and evidence. |
| /teacher/reading and /teacher/exercises | Teacher or Admin with authoring scope. POST create draft, GET scoped preview, PATCH draft using revision, PUT ordered paragraphs or question groups, POST publish/unpublish/archive on scoped resources. Privileged author DTO includes typed key and editorial fields. Publish capabilities await O-13. |

Use explicit field allowlists and reject unknown/mass-assignment fields. Question learner projection carries id, type, position, prompt, points, public instructions and answer constraints plus options where relevant. Keep correct IDs, accepted variants, correctness, explanation, evidence, internal moderation and storage fields out of discovery/recovery payloads. Exam pre-submit responses omit Learning aids and marks of correctness. Never share-cache private, CSRF, authoring or review responses. Propose no-store for these and initially for public API data where withdrawal freshness matters. Apply equivalent policy to SSR, prefetch, hydration, logs and error paths. Store/render plain text by default.

For restricted content, propose concealment in learner discovery until an explicit grant model is approved. Sign-in alone grants no restricted access. Teachers use scoped author tools; teacher role alone does not confer learner history access. Admin private support access requires a separately scoped and audited workflow. Session ownership and version membership are verified on every nested write. Exam-assistance enforcement applies server-side within the attempt experience, including any attempt-scoped dictionary endpoint. D02 keeps public Reading available independently and D05 permits legitimate earlier reviews. Exam Mode cannot guarantee closed-book integrity against material available outside the attempt. Owner acknowledgment is required before AC-10 is signed off.

## Deterministic grading proposal

| Type | Learner answer | Protected key and grading |
| --- | --- | --- |
| MULTIPLE_CHOICE_SINGLE | selectedOptionId | correctOptionId. Validate membership then compare UUID equality. |
| TRUE_FALSE_NOT_GIVEN | value in TRUE/FALSE/NOT_GIVEN | Same enum shape. Exact equality. |
| YES_NO_NOT_GIVEN | value in YES/NO/NOT_GIVEN | Same enum shape. Exact equality. |
| SHORT_ANSWER | text | Nonempty explicit accepted variants. Compare exact normalized strings within word limit. |
| SENTENCE_COMPLETION | text for one blank | Same comparison as short answer. Publish one blank per question with its own allowed variants. |

Grade with full fixed-precision points or zero. Null/normalized empty is unanswered. Malformed payloads, irrelevant fields, invalid options and over-size input are rejected without changing state. A syntactically valid over-word-limit response is saved and graded incorrect. Publish positive maxWords and the learner-visible instruction for both text types. Proposed policy v1 uses Unicode NFC, trims and collapses Unicode White_Space to ASCII space, counts space-delimited nonempty tokens with at least one Unicode letter or number (hyphenated words and contractions count once), and does locale-independent lowercase where case-insensitive. Preserve punctuation, accents and digits for equality. Pin the Unicode/runtime behavior with the policy revision. Validate authored alternatives for nonempty normalized text, nonzero token count, limit and uniqueness after normalization. If Unicode rules or word-count conventions change, issue a new policy version. Use no fuzzy matching, partial credit or inferred IELTS bands.

## Attempt lifecycle and retries

- Start resolves current publication and access in the transaction. Same learner and key with the same exercise/mode returns the original attempt with 200, even after ordinary withdrawal or a new publication. A different request under the same key returns 409. Concurrent same-key requests have a single winner through the unique constraint. Retain the request identity with the attempt. A new key starts a separate attempt while eligible, including when earlier attempts are active. Throttling is temporary abuse control.
- At start, pin version and deadline. Learning has no enforced deadline under the proposal and feedback is revealed after final submission pending O-07. Exam requires a positive duration, authoritative server clock, navigation, persisted review flags, a client countdown and a manual submit confirmation. Resolve elapsed time on the backend; refreshing never extends the deadline.
- Serialize saves and finalization using the same attempt row lock. Evaluate the deadline after acquiring the lock. Within IN_PROGRESS, identical full-state saves are successful no-ops with the current revision and timestamp. Different payloads using a stale revision receive 412. Identical replay after finalization receives a locked-state 409 with recovery through GET. The client reconciles stale writes from the current item revision.
- At or after deadline, freeze and grade the last committed answers, including blanks. Propose a periodic backend sweep and on-demand finalization through submit. Use the deadline as the effective submission time and record actual grading time. GET recovery reports items as read-only after the deadline. Result and review return 409 RESULT_PENDING until finalization commits. The client can submit to receive the committed expiry result immediately. Owner to approve sweep cadence and recovery behavior.
- Manual submit and expiry share one transaction to freeze, grade and persist the complete result. Return the existing committed summary for duplicate submissions and concurrent expiry. Roll back on grading/persistence failure. A later finalization can retry; no durable intermediate SUBMITTED state is needed for synchronous MVP grading. Missing answers never block submit. Cancel, randomization and restricted retake policy remain open.
