# M2.1 catalog foundation acceptance

**IN PROGRESS · NOT ACCEPTED**

## Scope and implemented checkpoint

V13 already delivered Course, CourseLevel and ReadingLesson. V14 adds the P04 capability grant storage and the catalog audit storage. It enforces distinct grantor/grantee, GLOBAL scope, one effective grant per grantee/capability, consistent revocation metadata, restrictive actor/target FKs and a single typed catalog target per audit record. Indexes support active grants, grant history, FK lookups and audit by resource. V14 creates no logins, mappings, runtime grants, authoring routines or HTTP routes.

Catalog write input validation now has a separate typed parser for course, level, lesson and status. It accepts UTF-8 JSON up to 32 KiB, caps JSON nesting at two, rejects duplicate and unknown fields, and applies the existing text, normalization and exact integer rules. HTTP admission, CSRF, ETags, lifecycle transitions and error mapping still require the staff runtime integration.

## AUTH integration checkpoint

Product Owner decisions A–C authorize a narrow staff AUTH integration, keep catalog UI in M2.6 and allow parallel independent M2.2 storage. [Intake manifest](M2-PARALLEL-INTAKE-MANIFEST.md)

`StaffAuthentication` reuses the M1 cookie lookup, AUTH token matcher, session registry and existing JVM account guard. It checks the selected reader or writer database principal, locks the actor row on that connection with the existing routine, then validates the current session under the JVM guard. The callback receives the transaction-bound JDBC client and the actor UUID/revision. Its scoped database routine must validate capability and scope and materialize the result before returning. The guard outlives transaction completion. No separate identity transaction, second session mechanism or wildcard route was added.

`CatalogHttpInput` connects the typed parser to a bounded servlet request read and validates filter cardinality, maximum page/offset and strong If-Match syntax. The contract tests exercise the adapter directly. No staff HTTP routes or catalog database command routines are wired at this checkpoint.
