## Delivered and exercised

| Scope | Evidence |
| --- | --- |
| Reading request contract | Typed Passage and Exercise creation and draft input, strict UTF-8 JSON, field and request limits, NFC normalization, five exact question discriminators, typed marking, and canonical modes with conditional integer Exam duration. |
| Edit rules | Domain rules check exact root and edition, draft state and expected revision from the supplied snapshot. They retain paragraph UUIDs across edits and reorder, assign one-based positions, request IDs only for new paragraphs and refuse to remove referenced paragraphs. Exercise validation checks that the pin belongs to the stable Passage and every Evidence UUID belongs to the exact edition. Tests use synthetic snapshots. |
| Preview and private fields | Exercise preview excludes marking, accepted answers, explanations, Evidence and points. The browser renders author text through ordinary React nodes. Draft data is fetched through no-store same-origin requests, kept in mounted component state and cleared on access denial. |
| Frontend | Passage and Exercise draft lists at /teacher/reading and /teacher/exercises, plus their respective /[id]/drafts/[draftId] editors. They consume the specified list, create, draft detail, draft PUT and exact Passage edition contracts. Mutations use AUTH CSRF and PUT sends the server's strong ETag as If-Match. The editor keeps unsaved edits after a revision conflict, offers comparison and shows a bundle preparation indicator for a draft Passage pin. |
| Runtime and persistence | No new Spring endpoints, migrations, grants, database writes, catalog changes or public endpoints in this checkpoint. Edge contract tests intercept the relevant API requests with synthetic responses. |

The editor uses a run of three or more underscores as the sentence-completion blank. The design specifies one blank and leaves its literal spelling open. The translations input normalizes BCP 47 tags with the JDK. Confirm both choices at integration. The input byte checks bound this checkpoint. Persisted graph size, round-trip response size and transaction budgets still require G03 evidence. [API contract](M2-API-CONTRACT.md)

2. **G02 and F04 integration.** The shared staff adapter must provide the trusted AUTH actor and expected security revision on one primary JDBC connection and outer transaction. Reads acquire the exact lockAndCheckActor(uuid,bigint) fence using the dedicated staff reader before the binding, capability and scope checks. The read retains the fence through DTO materialization. Writes keep the actor fence, edit capability check, Passage-before-Exercise locks, revision CAS, complete graph update and audit in one transaction on one connection. Live acceptance still needs role/privilege evidence, authorization and CSRF checks, revoked session and fence ordering tests, and real rollback and revision races.
