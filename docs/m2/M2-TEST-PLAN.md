## Targeted acceptance contracts

### T08 and T11 · Protected staff read and revoke

- Enumerate catalog and content list/detail, Passage exact edition, Exercise and Passage draft/preview, publication history and reconciliation. For each verify ACTIVE and exact revision/generation/capability/scope, no deferred DB lookup after transaction end, and no protected response on auth or fence failure. In race fixtures, remove the actor's final content capability or change security revision as applicable.
- Use real PostgreSQL, two independently checked-out connections, barriers and lock observation. Reader-first: pause after reader obtains fence and before materialization. Start revoke and observe it blocked on the same account row. Release reader; assert complete DTO was materialized under fence, with reader transaction completion before revoke commit. Revoke-first: hold revoke's account row while read attempts admission. Commit revoke; assert the stale session is denied before projection starts and response contains no protected data. Assert transaction order, not network packet order.
- Verify using the actual staff pool login and connection instrumentation that the same account row fence, scope checks and complete DTO materialization share backend PID and outer transaction. Verify effective USAGE on account_fence_routines and EXECUTE on the exact lockAndCheckActor(uuid,bigint) signature. Check the scoped projection allowlist and its non-login owners' column grants. Deny lockForLogin, direct table or view reads, all business/account writes, role assumption, operator/approver inheritance, schema CREATE, unrelated routine execution and PUBLIC access. Revoke the narrow grant only in an authorized test fixture; verify failure closed and no projection. Compare business and audit tables before/after GETs. Verify governance audit and revision change remain atomic on revoke.

### T14 · Passage paragraphs and Evidence

- Create a draft with two paragraphs and pin Evidence to one. Reorder, then edit its content. Assert the same UUIDs, expected one-based positions, new text and unchanged Evidence target. Add a new row without passing an ID and assert the response returns a distinct server-generated UUID. Read the exact scoped edition using the Evidence selector.
- Reject duplicate, malformed or null supplied IDs (400), unknown, cross-edition and cross-root UUIDs (uniform 404), and deletion of a referenced paragraph (409). Include valid content, order or translation changes in invalid requests and assert those changes, applied revision and Evidence remain unchanged. For concurrent new Evidence vs deletion, use Passage-lock barriers and assert no committed orphan in either ordering.
- Retain existing checks for exact pins, no automatic repin, frozen mutation denial, standalone freeze on draft pin rejected, atomic valid bundle and full rollback on invalid bundle.

### T16 · Publication concealment and recovery

- On the primary, seed a committed receipt and compare absent UUID, same-root other-actor receipt, other-root receipt and inaccessible root. Assert 404 with identical code/message/details and equivalent body shape, trace-ID format and length, relevant headers and no-store policy. Assert no receipt/actor/timestamp metadata or conditional cache headers. Correct actor/root gets 200 COMMITTED and the permitted result. Unauthenticated caller is denied.
- Drop the HTTP response after commit. Verify reconciliation by the original UUID routes to the primary, bypassing caches and replicas, and returns the stored result. Replay the same UUID/intent, including after pointer moves. Change the payload as the authorized actor/root only after a committed receipt binds the UUID; assert 409 OPERATION_CONFLICT without a new effect. Exercise concurrent matching retries and global PK collisions across lock sets. Assert exactly one durable receipt, one linked success audit and no partial frozen graph or pointer changes from the losing transaction.
- Hold the original execution before commit with a barrier. While the operation is unconfirmed, assert UNKNOWN in the client after the configured wait fails to produce an authorized receipt. Same-actor lookup may wait behind the account fence or return bounded generic 503. Release the barrier and verify authorized lookup/retry after completion. The client never infers rollback from lookup.
- Force rollback and verify no receipt, audit or pointer mutation on the primary. Later lookup returns the same concealed 404 as a never-started UUID. Original execution evidence may establish rollback; the lookup alone leaves an uncertain client at UNKNOWN, with no success, failure or rollback claim. Retry with the original UUID and intent and verify exactly one durable effect. After reload without the original payload, assert lookup remains available and no retry, replacement payload or automatically generated UUID is submitted. There is no test expecting the server to detect all changed payloads following rollback without a receipt.

### T18 · Exercise edition modes and duration

- Across DTO/service, guarded persistence and freeze, save and publish LEARNING with NULL duration, EXAM with valid integer duration, and LEARNING+EXAM with valid integer duration. Exercise 1 and 86400 as valid limits. Verify exact published edition projection for both fields and frozen history unchanged after successor publish. Confirm stable Exercise stores no mode/duration copy.
- Reject empty array, duplicate mode, NULL element, unknown mode, EXAM without duration, LEARNING-only with a duration, fractional duration, 0 and 86401. DTO must reject fractional numbers before coercion. Assert no partial change on invalid inputs. Frontend never generates duration with EXAM off.

Coverage is specified for future implementation. No database, runtime or browser implementation tests were run for v1.2.
