# M2.2 Reading staff persistence proposal

2026-11-27 · Agent B · integration checkout

PO-07 keeps Exercise, Evidence, the question graph, answer keys and marking in M2.3. PO-08 limits M2.2 to backend Reading authoring. Staff editors remain in M2.6. [Decision register](M2-DECISION-REGISTER.md)

## Schema and ownership

- V15 provides private Passage, PassageVersion, Topic, Paragraph and Translation storage. Its exact-root current and base pointers, one-open-draft index, deferrable per-edition paragraph order and frozen guards stay intact.
- V17.2 is the Integration Owner's private Passage-to-ReadingLesson placement relation. It preserves the Catalog Lesson identity, supports an unassigned tombstone and adds no role or runtime grant. Use a guarded Catalog writer boundary before exposing placement.
- V18 is reserved for M2.3. Draft and placement routines and the typed audit extension are pending separate Integration Owner allocation. Keep all staff Reading routes off until G02 and G03 and verify clean and upgrade paths before activation.
- All entry points bind the AUTH actor UUID, expected security revision and, for writes, an opaque server request UUID. No role creation or runtime table grants. Only the corresponding scoped reader or writer login receives EXECUTE on each approved projector or command. Their separate non-login owners receive narrowly scoped table/column privileges including what the V15 guards require. Use fixed search paths, schema-qualified references and explicitly revoked PUBLIC defaults.

## Proposed routine contract

The disabled HTTP candidate expects these signatures in a private reading_staff schema. Arguments follow the order below. PostgreSQL returns JSONB projected to explicitly permitted fields. The Java code decodes into typed records on the fenced connection and fully materializes the dedicated safe staff preview before leaving the transaction.

| Routine and arguments | Role and result |
| --- | --- |
| check_access(uuid actor, bigint security_revision, boolean editing) | Appropriate reader or writer. Returns true or raises the classified error. Use only for malformed request syntax before returning the error, preserving authorization precedence. Does no business read or write. |
| list_passages(uuid actor, bigint security_revision, integer page, integer size, text q, uuid topic_id, text state) | Reader. Return {data,page}, with bounded summaries and exact count in one snapshot. Exclude archived roots and full paragraphs. Bind literal title/slug search with optional topic and state filters. |
| get_edition(uuid actor, bigint security_revision, uuid passage, uuid edition, boolean draft_only) | Reader. Return exact PassageAdmin with ordered paragraphs and translations. Validate the edition under the supplied root, and require DRAFT when draft_only is true. |
| get_preview(uuid actor, bigint security_revision, uuid passage, uuid edition) | Reader. Return {revision,preview}, with exact draft membership and only StaffPreview fields. The preview contains the draft marker and safe display content. Revision is only used for the ETag. |
| mutate_passage(text action, uuid actor, bigint security_revision, uuid passage, uuid edition, jsonb input, bigint expected, uuid request_id) | Writer. CREATE receives validated slug/title and null tuple, CLONE receives exact root and baseVersionId in input, EDIT receives root/draft and normalized graph. Return full PassageAdmin, including revision and all paragraph UUIDs after mutation. |
| set_placement(uuid actor, bigint security_revision, uuid passage, uuid lesson, integer position, bigint expected, uuid request_id) | Writer. Verify current Catalog edit authority, Passage and Lesson scope and pair shape. Return {lessonId,position,revision}, including the new tombstone revision on unassignment. |

CREATE writes the stable row, initial private draft and audit together. CLONE locks the stable Passage, verifies that the chosen base is its frozen edition, ensures no open draft, then copies allowed fields and creates new descendant identities. EDIT locks the stable Passage, verifies exact draft membership, checks fields and all supplied UUIDs, applies revision CAS, and updates retained paragraphs in place. Defer the V15 position uniqueness constraint during reordering. Allocate a new UUID only for an omitted paragraphId. Validate topic scope before updating. Delete dependent translations before deleting omitted paragraphs and preserve untouched identity. Normalize translation language tags in the HTTP layer and validate stored constraints in the command. No Exercise- or Evidence-dependent deletion rules are implemented in this milestone.

The fence is acquired first on the same primary connection, before the JVM account guard and resource locks. Reads hold it through complete projection. Writers hold it through business mutation, CAS, projection, audit and commit. Placement must acquire Catalog hierarchy locks in the approved order with the Reading root before changing any relationship, using deterministic target order when old and new lessons differ. Confirm the precise cross-module lock order before writing the routine. Lock the stable Passage row even when no placement exists. Compare absent revision 0 only while holding that lock. An unassign writes a null lesson/position tombstone with advanced revision instead of deleting the placement row.

Extend the shared V14 audit with typed Passage and placement targets, not a second audit store. Add a restrictive Passage FK and composite Passage/edition FK. Authoring audit requires both IDs. Placement requires Passage and a null edition. Retain exclusive Catalog target validation, existing routine signatures and grant boundaries. Store actor, operation, request UUID, resulting revision and UTC event time. Keep body and translations out of audit. The writer inserts one success record in the same transaction as the validated operation. A rejected or rolled-back operation leaves neither a success audit nor a revision advance.

If extending the V14 enums and constraints in one transactional migration, express compatibility checks against enum text. Newly added enum constants cannot be consumed as enum values until the transaction commits. The guarded PL/pgSQL statements that INSERT the new values execute only after migration commit. Verify fresh and upgrade, including preservation of real Catalog fixtures and effective privileges.

## Error and bounded-work contract

- Body transport and byte checks run before AUTH. Authentication and scoped CSRF precede syntax errors. Valid requests apply current capability and scope in PostgreSQL. Use RD001 invalid input, RD002 forbidden, RD003 concealed not found, RD004 invalid state, RD005 missing If-Match, RD006 stale revision, RD007 malformed If-Match, RD008 stale AUTH and RD009 duplicate slug. Non-classified database failures fail closed. Java passes null for missing If-Match and -1 for malformed. Strong quoted zero is accepted only as the absent placement revision. Check scope and state before missing or stale revision.
- Reader accepts CONTENT_EDIT or CONTENT_PUBLISH as derived CONTENT_VIEW. Writer requires CONTENT_EDIT and placement requires the approved CATALOG_EDIT mapping. Validate session_user, effective routine owner, ACTIVE ADMIN, fence revision and current scoped capability.
- The candidate route gate is base.reading.enabled, false by default. No runtime database bean is provided. Candidate list bounds are page 0–99 and size 1–50, with a 100-scalar literal query. Transport accepts no more than 768 KiB and the graph uses the proposed 512 KiB input ceiling. These limits need G03 acceptance, including persisted graph cardinality, per-paragraph translation counts, DTO size, worst-case list/count and bounded transaction duration. Do not activate based solely on candidate limits.

## Integrated V17.3 disposition

The V17.3 allocation and verified migration supersede the early draft's pending allocation and stable-Passage locking suggestion for placement. Placement takes the account fence, old and new Catalog roots, levels and Lessons in deterministic order, then the placement row. It rechecks the observed prior Lesson and revision and uses unique-key CAS for insertion. Placement has no explicit Passage authoring write fence. V17.3 extends the existing typed audit relation. Archived roots are excluded from the protected list and cannot spawn new drafts. Exact historical editions remain readable under ordinary F04 scope checks. V18 and V19 remain reserved.

### Initial operational graph envelope

Under the isolation and cardinality directive, the Integration Owner selected at most 32 paragraphs and two translations per paragraph for the initial staff HTTP authoring envelope. Thirty-two paragraphs matches the previously measured normal draft shape. The translation count bounds graph fan-out while retaining multilingual authoring. The existing request, normalized SQL payload and response byte limits remain independent. Keep V17.3 unchanged. Validate both graph counts before an HTTP edit reaches the database mutation, and verify that at-cap and one-over tests retain revision and audit consistency. An operating inventory of any imported or restored frozen clone sources must satisfy the same counts before those sources become eligible for authoring. Exact historical staff reads retain their F04 protections.
