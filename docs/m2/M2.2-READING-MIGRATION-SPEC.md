Status **proposed, awaiting Integration Owner allocation**. PostgreSQL 17.12. Governing contracts are [M2 ERD v1.2](M2-ERD.md), [staff API](M2-API-CONTRACT.md) and [security design](M2-SECURITY-DESIGN.md). This proposal allocates no Flyway version and contains no executable migration SQL.

## Proposed private relations

All identifiers and references use UUID. Required columns are non-null unless marked optional. Use existing Reading state and visibility types. All foreign keys are restrictive on update and delete. Align lifecycle columns with V15 and use existing identity users.

Use exact array equality for LEARNING, EXAM, or canonical LEARNING+EXAM. The Exam duration range is 1–86,400 when EXAM is present and null otherwise. Enforce draft/frozen timestamp coherence, frozen same-family clone lineage and immutable frozen descendants. Stable identity has no copy of edition modes. An evidence locator is optional. Within a question, repeated references to the same paragraph and normalized locator are duplicates, and distinct locators remain valid. Review that storage uniqueness with the coordinator before migration allocation.

Draft create, save and clone audit requires coordination with the approved content audit contract and Catalog’s existing typed audit storage. Record a UUID event, trusted identity actor, operation, entity discriminator and a single typed stable/edition tuple, request UUID, resulting revision and UTC event time. Bind the tuple to the matching stable/edition key. Keep audit append-only and omit graph payloads, marking and explanations. Do not add a parallel shared audit store.

## Authority and transactions

- Keep schema and tables private to approved non-login owners, with no runtime direct table access or PUBLIC EXECUTE. Preserve V15 grants. Revoke default routine privileges and use schema-qualified references and fixed safe search paths. G02 controls actual principals and credentials separately.
- Staff read uses the existing M1 AUTH seam on a dedicated staff reader transaction with the exact approved F04 fence. Scoped projectors authorize derived CONTENT_VIEW and materialize the full requested DTO under the fence. Provide a separate preview allowlist that cannot read marking, explanations or Evidence.
- Staff write uses scoped author routines, identity-derived ACTIVE ADMIN actor and CONTENT_EDIT after AUTH CSRF. Acquire the DB account fence before the JVM stripe, then Passage root before Exercise root for pin/Evidence changes. Commit revision CAS, retained paragraph updates, allowed removal, graph and audit together. Reject cross-root or wrong-edition objects with concealed 404. Stale valid writes return 412. Evidence-referenced paragraph deletion returns 409.
- Validate payload and graph limits before locks wherever transport ordering permits. Confirm G03 before activating queries or authoring endpoints. No publication, attempt or public discovery tables or privileges are proposed.

## Installation and acceptance

Fresh installation applies accepted migrations through the allocated version. Upgrade runs from its previous accepted version, populates new private tables without rewriting V15 data, and validates original Flyway checksums. Catalog placement must follow both V15 and the verified Catalog prerequisite. Confirm schema ownership, effective privileges and preserved M1 account status/revision on both paths.

On the actual allocated schema, test all three Evidence FKs and exact pin FK, null and duplicate reference behavior, cross-family clone denial, frozen parent/child immutability, private grants, marking option/question membership and duration boundary splices. In two-connection tests exercise evidence-insert versus paragraph-delete in both lock orders and concurrent revision CAS. Verify atomic audit and rollback, scope concealment, account revoke/fence order and same-connection DTO materialization. Measure representative AUTH and fence-inclusive workloads for draft read, paragraph edit, Evidence checks and Exercise edit with query counts, acquisition, lock and transaction latency. The current V15 FK fixture does not exercise these future relations in an integrated migration.
